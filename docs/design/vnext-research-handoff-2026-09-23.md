# 下一代 TabU 方案：从 V5.4 拟合实验承接的问题

2026-09-23 的研究交接稿，**不是新的设计权威或已批准的默认配置**。当前权威仍是 owner 维护的 V5.4 TeX 与[实现说明](restoration-v54.md)。先据[old120 逐表阶段报告](../reports/v54-old120-fit-handoff-2026-09-23.md)提出下一代需要回答的问题；用户后续决定应回写新的 owner 设计源，再建立独立实现身份。

## 已经得到的边界

V5.4 已在单表、五表联合和 120 表训练行拟合上取得可见进展。2026-09-23 快照显示三路当前 v2 任务都还在训练；57 张数值目标表的当前固定 Query R² 均高于各自可见支持均值参考，离散表仍有明显尾部。模型结构、父权重、曝光、设备精度和训练预算未配对，因此不能把当前三路当作 Nano、标准 Small、Small-H4 的公平尺寸排名，也不能用它们证明高损失加训优于均衡训练。reserved/final_test 和未见表泛化尚未进入本轮证据。

保持已明确的实验合同：组合编码 `constant_weight_composition_v1`；当前 `supervised_row` Query-only；`random_cell` 是训练稳定后重点验证的第一备选；Nano 是重要模型候选。下一代可重新评估这些选择，但现有证据不足以默默替换默认。阶段资格仍按单表拟合 → 联合拟合 → 大量表拟合 → 持续学习/抗遗忘 → 真实数据预训练与微调 → 未见表泛化推进。

## 两个需要解耦的设计轴

**资源分配。** 现行 120 normal + 42 extra 的 P99×3/P95×2/P80×1 实际调度正确，但截至上述快照，三个任务的全部新增 extra 都去了数值目标，63 张离散目标表得到 0 extra；部分离散表低于多数类参考。下一代应把以下方案作为竞争选项：

1. 保留 raw loss 全表排名，作为既有对照。
2. 按 numeric／nominal／ordinal 分层排名并给定每类可核对的额外配额。
3. 用同一表的固定 Query 相对可见支持参考、近期改善或稳定化的训练损失作难度信号，再排序；需防止用测试集或未来 checkpoint 信息泄漏到调度。

三者在**相同 actual 更新预算**下比较，另同时列出各表 normal/extra 曝光、当前与输出内最佳固定 Query、类型尾部、速度和遗忘。不能只展示全表平均或训练 loss 分位数。不同类型原始损失的量纲是实际观测到的调度问题；哪种新办法最好仍须实验。

**模型增长。** 已完成的 Small-H4 变体增加一层 backbone 和 Unit 深度，通过新增残差出口零初始化保留起点函数。用户另提出仅将已训练 Nano 的两层 Token dynamic 串联复制四份，形成 8 层／4 heads／Unit0，编码与 readout 不复制。它已在 Jarvis 做同后端起点对比：数值 57/57 张表 R² 降低，中位数从 0.9786 到 -0.0837；nominal 准确率中位数从 0.8978 到 0.5700，ordinal 从 0.5625 到 0.4203。训练已启动，后续能否恢复未知。证据与数学边界见[模型增长研究](../research/v54-model-growth/README.md)，不能把一般残差网络误说成幂等。两种初始化应分别评估起点固定 Query、有限性、每步耗时、恢复/改善曲线和参数独立性，再决定是否推广为通用扩深工具。结构可接受任意有限层数不等于任意层数都值得训练。

截至 2026-09-23 03:02 UTC，Jarvis 已到 3,306 次实际更新，原始梯度范数最大 `1.44e12`、loss 最大 `1.23e5`；裁剪后仍有限，训练并未终止，但尚无 step0 以外的固定 Query。三项 old120 v2 共用同一 41 文件冻结训练源码，Jarvis 的 CUDA 目标裁剪 readout 优化已在真实更新日志中执行；[故障诊断](../../experiments/local/v54-nano-dynamics4x-old120-jarvis-20260922/failure-diagnosis-20260923.md)与[代码对比](../../experiments/local/v54-nano-dynamics4x-old120-jarvis-20260922/code-comparison-20260923.md)因此把“旧版未优化代码”和“复制扩深的训练稳定性”分开。W&B 一度显示 `Failed` 源于独立 observer 的 SSH 超时，现已在同一 run 恢复，不是模型训练终态。下一代增长方案需要将函数保持的扩深、原样复制，以及受控缩放/门控作为独立候选，并用同设备同初始化年龄的短程对照检验稳定性；具体配方仍待实验。

## 下一轮最小验证合同

先固定同一训练表集、target 列、训练行 Query bank、源码/数据/模型身份、设备精度、checkpoint 选择和 actual 更新预算；每个对照只改变一个拟研究因素。给新输出单独记录父检查点 SHA、weights-only 或完整 optimizer/RNG 迁移、step0 当前值及逐表曝光。每 120 normal 轮监控 mean／median／P05／P95／P99，extra 单独记；固定 Query 是拟合判据。若启用新 W&B run，应独立接入和云端读回，不改变用户现有精确三路过滤工作区。异常先定位，避免机械重启或无意追加预算。

完成训练行尾部和抗遗忘检验后，再决定下一阶段数据与评估权限。新的数学方案、默认配方或 held-out 评估须由后续 owner 设计明确；本交接稿只列问题、约束和可反驳的比较路径。

# Puma 风格稀疏信号诊断（2026-09-27）

**判断**：当前 Small H4 / Unit3 TabU 不是不能处理 32 列。相同非线性目标在 32 列都含有效信息时，150 更新的测试 R² 达到 `0.210`；若只有 6 列有效、其余 26 列是独立干扰，同一更新数仅 `0.017`。增加更新至 1000 后，原 32 列测试 R² 升至 `0.063`，所以不能称为永远学不会；但它学习很慢，且曾在微调中把 Unit 行间差异压向均值。证据更指向 **稀疏有效特征的识别与行聚合/读出学习**，而不是原始输入单位或 32 列宽本身。

## 对齐协议

- 延续 [上一轮配对试验](../puma-synthetic-probe-20260927/RESULT.md)：8,192 行，前 6,553 行 train、后 1,639 行 test。原始 teacher 是 6 个相关列上的门控、正弦和交互项，目标标准差约 `0.036`，独立噪声标准差 `0.020`。`noise12`、`noise20`、`full32`、`dense32`、`signal6` 的行、目标和噪声完全相同；`linear32` 保留同一批行、6 个相关列、干扰列和噪声，只把 teacher 改成线性组合。
- 所有新 arm 都从同一个 OpenML12 H4/Unit3 父权重 `e3da2393…543863` **weights-only** 开始，优化器独立新建，目标均为 `squared`。`full32` 的 600→1000 是上一轮检查点的**严格续训**。执行路径是 deepthought 的 `wehub-python --profile train`，RTX 3070 Ti、CUDA/FP64；模型对每个数值列使用 episode 内 z-score。
- 每次训练更新使用 204 行，其中约 136 个可见标签 support、68 个隐藏标签 Query。测试用 8 个固定 episode：每次相同的 136 个 train support，分别预测 68 个 train Query 与 68 个 test Query，每组共 544 个预测。表中 `S_log` 均用训练集 median/MAD 定标。**这仍是固定窗口拟合诊断，不是全表 6,553+1,639 前向。**
- XGBoost 的 `136-support` 对照在每个相同的 episode 上只用那 136 个 support 重新训练 100 棵深度 3 的树，再预测相同 test Query；它对齐了推理时 support 数量和测试地址，训练流程/计算预算不同。另有 6,553 行训练池的 XGBoost 对照用于证明数据可学习。

## 短程结果

单元格为 `R² / S_log`；ESS 是带宽 `1.0` 下 136 个 support 的平均有效权重数，越大表示邻域越分散。`noise12` 因运行时间改为有意在 165 更新保存，比其余短程 arm 多 15 更新。

| 合成表 | 列数 | TabU 更新 | TabU train Query | TabU test Query | test ESS | XGBoost 136-support test Query |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `signal6`：仅 6 个有效列 | 6 | 150 | 0.181 / 0.118 | **0.203 / 0.126** | 3.0 | 0.402 / 0.246 |
| `noise12`：6 有效 + 6 独立干扰 | 12 | 165 | 0.044 / 0.029 | **0.043 / 0.038** | 6.1 | 0.368 / 0.209 |
| `noise20`：6 有效 + 14 独立干扰 | 20 | 150 | 0.036 / 0.021 | **0.025 / 0.021** | 18.7 | 0.365 / 0.216 |
| `full32`：6 有效 + 26 独立干扰 | 32 | 150 | −0.000 / 0.001 | **0.017 / 0.020** | 76.4 | 0.332 / 0.195 |
| `dense32`：其余 26 列复制有效特征 | 32 | 150 | 0.253 / 0.165 | **0.210 / 0.126** | 2.2 | 0.402 / 0.246 |
| `linear32`：32 列、线性 teacher | 32 | 150 | 0.178 / 0.100 | **0.130 / 0.060** | 10.8 | 0.443 / 0.313 |

6→12→20→32 列的相同目标阶梯说明，少量干扰列已经使相似度判断失准，随后权重逐步扩散。`dense32` 在相同列数下恢复拟合，排除了“32 列这个宽度天然不能学”的简单解释。`linear32` 好于非线性 `full32`，说明门控/交互进一步增加困难；但仍落后于同窗口 XGBoost，干扰列本身也有影响。完整 6,553 行训练池的 XGBoost 在 `full32` 上测试 R² / S_log 为 `0.616 / 0.445`；它不能与 TabU 的固定窗口直接比胜负，但确认规律可学。

## 继续训练与机制探针

`full32` 在相同固定 Query 上，从 150→600→1000 更新的测试 R² / S_log 为 `0.017/0.020 → 0.025/0.021 → 0.063/0.034`；测试输出标准差为 `0.00486 → 0.00549 → 0.00790`，而真值约 `0.03483`。1000 更新有小幅进展，仍远低于 `signal6` 在 600 更新的 `0.266/0.181` 和 `dense32` 在 150 更新的 `0.210/0.126`。1000 更新的 train Query R² 仅 `0.013`，目前也没有强烈的训练池拟合证据。

冻结权重逐层测量 Unit 行间 spread / 最终核 ESS：

| 权重、输入 | 父权重 | 600 更新 | 1000 更新 |
| --- | ---: | ---: | ---: |
| `signal6` 的 Unit spread / ESS | 6.19 / 2.8 | 5.84 / 2.4 | — |
| `full32` 的 Unit spread / ESS | 3.23 / 16.2 | **1.44 / 90.2** | 2.44 / 34.6 |

`full32` 的收缩从第二个 axial layer 已可见：父权重 spread / ESS 为 `3.73 / 10.4`，600 更新变成 `2.43 / 39.1`，经过 Unit blocks 后到 `1.44 / 90.2`。这说明 600 更新的趋均值不仅来自固定核带宽，还伴随训练中表征的收缩；1000 更新时有部分回升。

- **仅在推理时屏蔽 26 个无关列**：`full32` 600 更新权重的 test R² 从 `0.025` 变为 `0.011`；1000 更新权重从 `0.063` 变为 `0.078`，仍没有恢复到 6 列模型。方法校验：`signal6` 600 更新权重放在 32 列 schema 中并屏蔽其余列，精确复现原来的 `0.266`。屏蔽是分布外干预，所以这里只能断言“单靠推理时去噪不能救回已训练权重”，不能断言参数里完全没有相关信息。
- **冻结权重只改读出带宽**：`full32` 600 更新在带宽 `0.5 / 1.0 / 2.0` 下，test R² 为 `0.0256 / 0.0251 / 0.0241`；1000 更新为 `0.0675 / 0.0635 / 0.0631`。局部均值读出单独扫描带宽也未救回。这排除了“只要调一下固定高斯核宽度就能解决”的简单解释。
- **原始量纲**：所有列在每个 episode 内 z-score，目标训练标准差 `0.036` 远高于数值编码器 `1e-6` 的尺度下限。这里更关键的“尺度”是 Unit 表征行间距离相对核带宽及干扰列占据的注意力质量，不是原始角度/扭矩的单位换算。

一个计划中的 `constant32` 对照在 **0 更新** 被训练契约拒绝：`supervised numeric column needs two distinct visible values`。这是无效数据构造，不记为模型拟合失败；保留了失败回执，随后用 `dense32` 和 oracle mask 完成了列宽对照。

## 可操作的改进方向与边界

优先验证 **基于可见 support 标签、在行聚合之前抑制无关列的机制**，而不是单独调带宽或改损失。这个机制需允许门控和交互：原 teacher 的一部分有效列单看边际相关性也可能很弱，所以纯单变量筛选未必够。训练数据可系统变化有效列比例、干扰列数、线性/门控/交互，并把这组固定 Query R²、S_log、Unit spread 和 ESS 作为回归门槛。当前没有改动 TabU 模型源码，也没有把这一个合成 teacher 的结果外推成真实 `pumadyn32nh` 的已证实根因。

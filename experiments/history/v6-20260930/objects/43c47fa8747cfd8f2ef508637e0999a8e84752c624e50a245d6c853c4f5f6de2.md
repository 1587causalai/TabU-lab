# full32：首项 V6 改动的两项机制消融

本目录仅新增独立实现，复用已冻结的 full32 数据、DGX2 H8 父配置/权重与上一轮逐 episode 地址。未修改 V6 模型源码或原 probe。

| 变体 | 输入 | LL 支持响应 | 外层训练损失 | 正式 target 解码 |
|---|---|---|---|---|
| `broadcast-only` | V6 一次同行 target 广播；Null 为零，Unit/Feature 不广播 | 原始 `e_a(x)`；原可见支持资格 | 原 V5.5 Query 目标列平方损失 | 原 decoder，不除二 |
| `all-column-loss-only` | 原 V5.5 输入，不广播 | `e_a(x) + e_target(y)`；两分量均可见才能供响应 | V6 Query 行全列联合平方损失，行内列平均；保留 target 的四倍平方效应 | 联合 target 编码除二后解码 |

后一项是**联合响应与全列损失整体**的消融，不声称只增加了评分地址；没有偷偷改回单码答案，也没有以单码解码联合答案。

两个模型各从同一父权重 weights-only 初始化，新建相同优化器，分别完成 150 和 600 次更新对照。每个训练 episode 使用 136 support + 68 Query，table.name 与随机 namespace 保持原配对 probe 的统一值。每一步在更新前核对上一轮 `training-episode-bank.jsonl` 的行地址、Query 地址与 mask/code/window seeds。0 和终点在相同 8 组 136+68 train/test 窗口评估 R²、S_log、prediction_sd；S_log 沿原训练标签 median/MAD 标度。

固定表征下 LL 对响应线性，所以 0 更新时预期 `broadcast-only` 的正式 target 预测与完整 V6 一致，`all-column-loss-only` 与 V5.5 一致（允许浮点舍入差）。后续差异来自各自训练目标与输入的联合作用；不同 loss 数值不能直接比较。

`parameter_update_seconds` 累计成功的 forward、loss、backward、梯度检查/裁剪与 optimizer.step 时间，GPU 同步后计时；不含 episode 构造、checkpoint、评估。另记 episode 构造与评估时间。此处仅承诺等更新数，不承诺等计算量。
旧 probe 的 `train_step_seconds` 包含 episode 构造；比较运行耗时时须先对齐计时范围。

运行前由协调者分配 GPU。让 `PYTHONPATH` 指向原冻结 `source/src`，执行：

```bash
~/.local/bin/wehub-python --profile train-20260920 -u run.py \
  --probe-root /path/to/v6-sparse-relevance-probe-20260927 \
  --reference-run /path/to/previous-four-arm-run \
  --parent /path/to/parent.pt --parent-sha FULL_SHA256 \
  --output /path/to/new-ablation-run --updates 150 --device cuda:0
```

输出包含 campaign 身份、两变体的 0/终点评估与逐样本预测、逐更新日志、每 50 步 checkpoint、终态及汇总回执。实际结果和第二合成实例复现见 [RESULT.md](RESULT.md)。第二实例的单变体选择脚本为 `run_selected.py`，原 150/600 消融始终使用本目录的 `run.py`，各自的 SHA 保存在 campaign 回执中。

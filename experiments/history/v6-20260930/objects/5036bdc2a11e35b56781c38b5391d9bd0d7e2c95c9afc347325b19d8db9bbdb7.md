# V6 target broadcasting ＋旧 target-only 损失：OpenML12 共享训练

**状态：训练与四节点整表测试均已完成。** 2026-09-27 在 DGX2 H8 / CUDA FP64 / 固定 `train-20260920` 完成 **9,372 次更新、3,600.18 秒成功参数更新时间**。单一共享检查点从 V5.5 OpenML12 DGX2 30 分钟终点 `86f380c39c4da737eb92de301e1c69ac11c47304aa23b86ee034a40bfb3ad952` **weights-only** 初始化，重建优化器、RNG 和训练 cursor。训练沿用 12 张 OpenML 回归表与旧 618 表的冻结 630 表混合，每 20 更新中重点 Puma/kin8nm 各 3 次、其余 10 表各 1 次、旧表回放 4 次。实际梯度更新分别为重点 2 表 **2,811** 次、其他 10 表 **4,688** 次、旧 618 表 **1,873** 次。新默认 `supervision="target_only"` 仅对 Query 目标列使用 V5.5 平方损失；`supervision="joint_all"` 保留此前联合响应＋全 Query 行列损失为备选。两种模式都广播 target carrier，参数张量结构不变。

评价沿用冻结 OpenML12 bank：每表完整训练 split 作带标签 support，完整测试 split 作 Query，单次前向；12 表共 7,894 个测试目标。R²、S_log 均在解码后的 target 数值上计算。重点报告 `pumadyn32nh`、`kin8nm`，并查看 `cpu_activity`、`space_ga`、`white_wine`。目前只有 Puma 风格**合成**任务有受控的 26 个无关列证据；真实表的困难不能直接归因于同一机制。

前 827 次更新与上一轮“广播＋全列损失”逐步配对，cohort、table、episode index、Query 行数一致；新默认累计 **316.87 秒**有效训练，旧全列方案 **900.44 秒**，同一 DGX2 和 runtime 下约 **2.84 倍**速度。新模式每步只评分 Query target Cell，旧全列方案评分 Query 行所有观察列。详见[配对速度回执](receipts/matched-827-speed.json)。

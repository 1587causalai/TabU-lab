01 · 使命

让模型诞生的路径可检查。

“开放”不只是发布最终 checkpoint。促成模型的关键决策也必须足够可见，让另一位研究者——或另一个 agent——能够审计并继续。

A

按公开 recipe 训练

架构、数据准备、objective 与 compute 假设保留在版本化源码中，不藏在最终 metric 后面。

B

先在小规模上可复现

每个想法先在明确预算下取得信号。scale 是后续决策，不是理解机制的替代品。

C

把失败也发布为信息

当 protocol、日志和边界清楚时，被 kill 的假设也是有用结果。沉默的死路教不会任何人。

02 · 实验协议

每个实验都是一个有类型、可审计的工作单元。

Marin 展示了公开完整实验生命周期的价值。TabU-lab 把这个思想适配到 WeHub：简洁的 gate、精确的 execution receipt，以及先于综合结论的诚实 verdict。

  1. 01

    预注册

    执行前写下 hypothesis、baseline、预算和 pass / kill criterion。

  2. 02

    实现

    提交能够执行预期比较的代码与 config。

  3. 03

    运行

    记录 command、seed、数据 provenance、environment、host 与 compute。

  4. 04

    收据

    发布 raw metrics、曲线、日志、artifact，以及所有限制解释的因素。

  5. 05

    结论

    标记 pass、kill 或 revise；只综合 receipt 真正支持的内容。

RUN RECEIPT / 最小字段receipt.v0
  • hypothesis + gate
  • commit + config hash
  • dataset + split
  • seed + environment
  • host + compute budget
  • raw metrics + curves
  • failure notes
  • pass / kill / revise

04 · 研究方向

四个可以提出可证伪问题的地方。

这些是邀请研究的问题面，不是声称对应系统已经存在。

01

数据与先验

什么样的 synthetic 或 real-table distribution 能教会可复用结构，同时不隐藏 test knowledge？

02

表征

value、role、missingness、Unit 与表格结构，应如何成为 typed computational objects？

03

训练系统

哪些小规模 recipe 能在昂贵 scaling 前产生稳定的 learning signal？

04

评测

哪些 held-out tables、distribution shifts 和 negative controls 真正能够证伪所提机制？

05 · 加入实验室

带来一个可能输掉的问题。

最好的贡献不是宏大的承诺，而是一个清晰 hypothesis、一个匹配的 comparison，以及一份让后来者可以继续的 receipt。
